# 聚合放大镜

把每一种订单与退款组合展开，看清 SUM 为什么会多算。一款面向 SQL 学习者的单客户聚合教学网页。

## 运行

在项目目录运行 `python -m http.server 18084 --bind 127.0.0.1`，访问 `http://127.0.0.1:18084`。需要 Python 3，仅提供静态文件，无前端安装或构建步骤。请通过 HTTP 打开，避免 file 协议的 ES module 限制。

## 使用

切换默认数据、相同金额、单侧为空或两侧为空的场景；也可分别调整 0–5 笔订单与退款，并令两侧各自前两笔金额相同。组合矩阵展示原始明细连接后的一对一配对行，三种汇总方式并排给出订单和退款总额。点击“先聚合，再连接”查看客户级汇总，点击其他方式回到原始组合。

可复制当前查询或包含建表、数据和查询的完整实验脚本，在独立 SQLite 测试库复现。复制失败时页面提供可选中的完整脚本文本。

## 范围与数据

固定分析同一位客户，两张明细表都通过客户编号关联。组合不表示某笔退款属于某笔订单。它是固定语义模拟，不解析任意 SQL，不连接真实数据库，不提供结算或财务决策功能。

金额内部用整数分计算，SQL 输出为分，界面换算为元。数据只存在于内存，不上传、不持久化，刷新恢复默认。模型只在开发阶段辅助生成代码，运行时不调用模型。

核心模块支持每侧最多 50 条记录；ID 为正安全整数且表内唯一，金额为 0–100000000 分的安全整数。空侧以 NULL 补齐，展示金额经 COALESCE 语义归零。

## 开发与验证

核心 `analyze` 与 SQL 模板基础由华为云 AI 开发者空间 CodeArts 生成，随后将金额 DISTINCT 的 SQL 改为直接展示连接后的聚合，使教学代码与矩阵一致。界面与 SQLite 独立对照由 Codex 辅助完成。

`node --test core.test.js` 检查边界和校验；`python verify_sqlite.py` 对比核心金额与真实 SQLite 查询，并执行完整脚本。更详细记录位于投稿材料中。

参考：SQLite 官方《Built-in Aggregate Functions》、PostgreSQL 官方《7.2. Table Expressions》。
